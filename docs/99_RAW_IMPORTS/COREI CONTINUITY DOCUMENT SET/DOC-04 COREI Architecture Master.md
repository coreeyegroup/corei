# =============================================================================
#
# CHAPTER 01
#
# WHAT IS COREI
#
# =============================================================================

COREI is an Institutional Operating System designed to manage, coordinate,
operate and supervise every operational aspect of a modern trading and
financial intelligence organization.

COREI is not

• a trading application

• a dashboard

• a broker terminal

• a charting platform

• a reporting system

• an infrastructure console

COREI integrates all of these capabilities into one unified operational
environment.

The objective of COREI is to become the single operational workspace through
which an institution performs its daily activities.

# THE THREE-LAYER MODEL
#
# =============================================================================

One of the most important architectural discoveries during COREI development
was that every responsibility naturally belongs to one of three institutional
layers.

These layers are permanent.

They should not be reorganized simply because technologies evolve.

They describe responsibility,

not implementation.

They represent the operational structure of COREI.



Institution

↓

Operating Environment

↓

Execution Platform



Everything inside COREI belongs somewhere inside these three layers.



# =============================================================================
#
# CHAPTER 21
#
# WHY THE THREE-LAYER MODEL EXISTS
#
# =============================================================================

Originally,

COREI was being designed as one continuously growing software project.

As more capabilities appeared,

the architecture became increasingly difficult to reason about.

Questions repeatedly appeared.

Where should this capability belong?

Who owns this functionality?

Which repository should implement it?

Who depends upon whom?

Eventually,

a clear architectural pattern emerged.

The platform naturally separated into

Operating Environment

Institutional Platform

Infrastructure Platform

Once this separation became clear,

the architecture stabilized.

This model is now frozen.
