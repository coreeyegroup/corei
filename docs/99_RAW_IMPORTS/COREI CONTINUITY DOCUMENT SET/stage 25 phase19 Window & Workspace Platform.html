01 Executive Summary

Phase‑19 delivers the institutional Window & Workspace Platform – the operator‑facing environment that transforms the completed Platform Kernel (Phases 01‑16) into a professional workstation. It consumes the frozen Institutional Shell (Phase‑17) and Capability Provider Platform (Phase‑18), and operationalises existing workspace, window, docking, layout, viewport, persistence, and recovery foundations – without rebuilding them.

The phase is governed by the Platform Enablement philosophy:

Consume → Integrate → Coordinate → Operationalize → Validate → Freeze

The authoritative execution map defines 21 controlled steps (see §19), but the core engineering work is organised into six execution blocks that progressively build the operator experience.

At completion, Phase‑19 provides:

  • ✅ Deterministic workspace lifecycle
  • ✅ Institutional window management
  • ✅ Provider‑backed docking (Dockview consumed through COREI contracts)
  • ✅ Layout runtime and composition (splits, tabs, groups)
  • ✅ Floating windows and multi‑window coordination
  • ✅ Multi‑monitor readiness (logical topology)
  • ✅ Focus/presentation modes
  • ✅ Workspace switching and active‑context coordination
  • ✅ Persistence, serialisation, restoration, and recovery
  • ✅ Shell ↔ Workbench ↔ Workspace runtime integration
  • ✅ Event/state/lifecycle coordination
  • ✅ Diagnostics observability
  • ✅ Multiplicity and isolation validation

Current Status: Repository discovery completed; Step‑01 certified; Step‑02 (contract boundary) is the next implementation. Certification pending.

03 Architecture

The Phase‑19 architecture follows the institutional layered model established in the kernel. It is organised into six execution blocks:

  1. Repository Truth (Steps 01–02) – baseline discovery and contract boundary.
  2. Operational Foundations (Steps 03–06) – workspace, window, docking, layout coordination.
  3. Workspace Experience (Steps 07–12) – splits, tabs, groups, floating windows, multi‑window, multi‑monitor, focus.
  4. Persistence & Recovery (Steps 13–14) – persistence, serialization, restoration, recovery.
  5. Institutional Integration (Steps 15–16) – Shell ↔ Workbench ↔ Workspace runtime, events/state/lifecycle.
  6. Certification (Steps 17–21) – diagnostics, multiplicity, cross‑browser validation, final integration, freeze.

The target composition chain is:

Institutional Shell
    ↓

    ↓
WorkspaceHost
    ↓

    │
    ├── Workspace Operational Coordination

    ├── Layout Runtime
    ├── Layout Composition (Split/Tab/Group)
    ├── Floating Window Management
    ├── Multi‑Window Runtime
    ├── Multi‑Monitor Runtime
    ├── Focus/Presentation Modes
    ├── Workspace Switching
    ├── Persistence/Serialization
    ├── Restoration/Recovery
    ├── Shell/Workbench Integration
    └── Events/State/Lifecycle Coordination

The Shell remains a consumer; it never owns workspace internals.

19 Appendix

A. Phase‑19 21‑Step Execution Map

  1. Phase Entry, Repository Reality & Architecture Reconciliation – Baseline discovery; certification of existing capabilities and protected boundaries.
  2. Window & Workspace Platform Contract Boundary – Platform‑level contracts (identities, lifecycle vocab, snapshots) – no runtime.
  3. Workspace Operational Coordination – Workspace lifecycle coordination (create, open, activate, suspend, resume, close, dispose).
  4. Window Management Platform – Window registration, lifecycle, activation, focus, workspace association.
  5. Docking Runtime Integration – Connect Dockview adapter; synchronise logical workspace/window with Dockview runtime.
  6. Workspace Layout Runtime – Logical layout registration, activation, and mutation coordination.
  7. Split, Tab & Group Management – Structural composition (groups, items, ordering, splits).
  8. Floating Window Management – Floating state, geometry, reattachment, restore.
  9. Multi‑Window Runtime – Multiple operational windows; active/focus coordination; application runtime identity.
  10. Multi‑Monitor Architecture & Runtime Readiness – Monitor topology, primary monitor, runtime‑window assignment, placement.
  11. Workspace Focus & Presentation Modes – Normal, Focus, Fullscreen, Presentation modes with restoration points.
  12. Workspace Switching & Active Context Coordination – Deterministic workspace switch, no‑op semantics, active‑context projection.
  13. Workspace Persistence & Serialization Integration – Canonical persistence snapshot, deterministic serialisation, storage adapter port.
  14. Workspace Restoration & Recovery – Restoration validation, primary/fallback recovery, failure classification.
  15. Shell ↔ Workbench ↔ Workspace Runtime Integration – Integration coordinator and Workbench React provider.
  16. Workspace Events, State & Lifecycle Coordination – Event publication, state projection, lifecycle coordination through existing platforms.
  17. Window & Workspace Diagnostics / Observability – Platform diagnostics, health, logging (consumes Foundation services).
  18. Institutional Multiplicity & Isolation Validation – Multi‑workspace, multi‑window, isolation validation.
  19. Cross‑Browser / Viewport / Window Behavioral Validation – Chromium, Firefox, WebKit – workspace, docking, persistence, recovery.
  20. Phase‑19 Final Integration & Architecture Validation – End‑to‑end runtime validation, architecture audit, anti‑drift check.
  21. Phase‑19 Certification, Freeze & Consumption Handoff – Final certification, Git freeze, public API freeze, handoff to Phase‑20.

Critical rule: Each step's implementation scope is defined by the phase document; repository reconciliation determines the exact implementation delta within that scope, not the step sequence.
