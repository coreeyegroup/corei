	5.2 Reconciliation Rule (CRITICAL)
		IF external_event_exists:
			use external_event
		ELSE:
			reject system (no fallback)

		External Stream Completeness Rule (MANDATORY):

			external_event_stream is VALID only if:

			1. contains ORDER_ROUTED OR ORDER_FAILED
			2. IF any fill exists:
			   MUST terminate with FULL_FILL OR ORDER_FAILED
			3. Σ(executed_size) ≤ order.size
			4. events cover full lifecycle (no gaps)

			IF NOT:
				→ HARD REJECT (incomplete external truth)

	5.3 Source Priority Rule
		External Fill Events > Internal Events

	5.4 Rebuild Rule (MANDATORY)
		final_event_stream = rebuild_from_external(external_event_stream)

		Constraints:

			discard ALL internal fill events
			reconstruct lifecycle fully
			enforce Step 6 transition rules
			align with Step 7 reconciliation model

		Reconciled Event Ordering Key (MANDATORY):

			ordering_key = {
				event_time ASC
				order_id ASC
				event_type_priority ASC
				external_event_index ASC
			}

			All events MUST be sorted BEFORE rebuild.

		Lifecycle Completion Rule:

			IF cumulative_executed_size < order.size:
				→ DO NOT emit FULL_FILL
				→ final state = PARTIALLY_FILLED

			IF no terminal event:
				→ HARD REJECT

			Terminal states:
				FULL_FILL → ORDER_COMPLETED
				ORDER_FAILED

		Terminal Event Precedence Rule:

			ORDER_FAILED > FULL_FILL > PARTIAL_FILL

			IF ORDER_FAILED exists:
				discard all fill events AFTER failure

			IF FULL_FILL exists:
				no further fills allowed

		Partial Completion Rule:

			IF cumulative_executed_size < order.size:

				final state = PARTIALLY_FILLED

				ORDER_COMPLETED MUST NOT be emitted

		assign event_id deterministically USING:

			event_id = HASH_v1(
				order_id +
				event_type +
				executed_size +
				remaining_size +
				event_time +
				external_event_index
			)

		Global Ordering Uniqueness Rule:

			(order_id + external_event_index) MUST uniquely identify
			event sequence across system.

			Constraint:

			No two events across all partitions
			may share identical:

				event_time
				order_id
				event_type_priority
				external_event_index

		Event Type Priority Mapping (MANDATORY):

			ORDER_CREATED    = 1
			ORDER_ROUTED     = 2
			PARTIAL_FILL     = 3
			FULL_FILL        = 4
			ORDER_COMPLETED  = 5
			ORDER_FAILED     = 6

			event_type_priority MUST be used in ordering_key
			NOT string comparison

	5.5 Drift Detection Rules

		Detect:

		D1: size mismatch
		D2: missing fills
		D3: duplicate fills
		D4: ordering violation
		D5: state mismatch

		drift_flag = TRUE if:

		Σ(external_fills) ≠ Σ(internal_fills)
		OR ordering mismatch
		OR lifecycle mismatch

		Overfill Protection Rule:

			IF Σ(executed_size) > order.size:
				→ HARD FAIL

			Duplicate Detection:

			duplicate_key = HASH(
				broker_order_id +
				executed_size +
				event_time
			)

			duplicates MUST be removed deterministically
			(lowest hash retained)

		IF executed_size <= 0:
			→ REJECT event

		Duplicate Tie-Break Rule:

			IF hash collision occurs:

				use:
					event_time ASC
					order_id ASC
					executed_size ASC

		Numeric Model Enforcement:

			All numeric values MUST follow:

			value = integer / 10^6

			No floating point allowed

			remaining_size MUST use integer arithmetic only
