Phase D — Step 6: Order Lifecycle System

1. PHASE IDENTITY LAYER

	1.1 Phase Name

		Phase D — Step 6: Order Lifecycle System (Execution State Realization Layer)

	1.2 Phase Role

		Step 6 is a PURE INTERNAL LIFECYCLE SIMULATION ENGINE.

			It MUST:

				- generate deterministic execution events
				- simulate fills using configuration_snapshot.fill_model
				- drive OrderState transitions
				- update PortfolioState using INTERNAL events ONLY

			It MUST NOT:

				- consume external broker fills
				- reconcile external execution
				- override events from Step 7

			External execution truth is handled ONLY in Step 7 and Step 8.

	1.3 Phase Objective

		Construct:

			ExecutionOrder
			→ ExecutionEvent Log
			→ OrderState(t)
			→ PortfolioState(t)

		Such that:

			state = f(event_log)
			replay(EventLog) → identical state
			execution is audit-complete

	1.4 Why This Phase Exists

		Without lifecycle:

			Orders never evolve
			No fills
			No portfolio updates
			No audit trail

		Execution system is non-functional

		Aligned with Step 5 lifecycle init

		state transition engine

			ExternalFillEvent (from Step 7) MUST NOT enter Step 6.

		Lifecycle MUST consume execution events from:

			- OMS/EMS routed execution (internal)
			- OR Step 7 normalized events (external)

			BUT:

			- MUST NOT depend on OMS/EMS runtime state

		microstructure-aware fill simulation
			slippage realization engine
			transaction cost analysis (TCA)
			PnL computation (realized + unrealized)

	2.2 EXCLUDED (STRICT)
		order generation (Step 5)
		risk enforcement (Step 3)

		broker integration (future step)
		market microstructure

	2.3 Boundary Rule

		Lifecycle MUST:

		be event-driven ONLY
		NOT mutate state directly
		NOT depend on external systems

5. LOGIC / RULE ENGINE
	5.1 Rule Classes

		R1 — Event Generation
		R2 — Fill Processing
		R3 — State Transition

		R5 — Replay Validation
		R6 — Event Generation Function

				ExecutionOrder,

			)

			Constraints:

			- no randomness
			- no external input

		R7 — Slippage Realization
			realized_slippage = deterministic_function(
					execution_schedule,
					slippage_model
				)

				Constraint:

				must be bounded by Step 5 slippage_model

		R8 — Transaction Cost Computation
			transaction_cost = (
					executed_size × fee_per_unit
				) + fixed_fee

		R9 — PnL Computation
			realized_pnl = (sell_value - buy_value) - transaction_cost

		R10 — Batch Aggregation
			simulation_batch.total_pnl = Σ(pnl_record.net_pnl)

	5.2 State Transition Function
		OrderState(t+1) = f(
			OrderState(t),
			ExecutionEvent
		)

	5.3 Transition Rules (STRICT)
		OrderState Transition Model (GLOBAL)

		ORDER_CREATED		→ ORDER_ROUTED

		ORDER_ROUTED		→ PARTIALLY_FILLED
		ORDER_ROUTED 		→ FULLY_FILLED
		ORDER_ROUTED 		→ ORDER_FAILED

		PARTIALLY_FILLED 	→ PARTIALLY_FILLED
		PARTIALLY_FILLED 	→ FULLY_FILLED
		PARTIALLY_FILLED 	→ ORDER_FAILED

		FULLY_FILLED 		→ ORDER_COMPLETED

		ORDER_FAILED 		→ terminal
		ORDER_COMPLETED 	→ terminal

		Constraints:

			monotonic transitions only
			no skipping states
			invalid transition → HARD FAIL


		FULL_FILL Rule:

			- MUST occur exactly once
			- MUST be last fill event
			- AFTER FULL_FILL → no further PARTIAL_FILL allowed

	5.4 Fill Processing Rule
			remaining_size = order.size - Σ(executed_size)

		Constraints:

			remaining_size ≥ 0
			remaining_size == 0 → FULL_FILL

		(Aligned with Step 5 invariant )

		Fill Generation Model:

			executed_size_i = f(
				remaining_size,
				configuration_snapshot.fill_model
			)

			Constraints:

			- deterministic partitioning
			- Σ(executed_size_i) = order.size
			- final event MUST be FULL_FILL

		Numeric Constraints:

			executed_size:
				min > 0
				max ≤ order.size
				type = fixed-point (integer / 10^6)

			remaining_size:
				min = 0
				max = order.size

	5.5 Portfolio Update Rule
			PortfolioState(t+1) = f(
				PortfolioState(t),
				ExecutionEvent.executed_size,
				direction
			)

		BUY:

			position += executed_size

		SELL:

			position -= executed_size

		Portfolio Value Update:

			total_executed_value += executed_size * execution_price

		execution_price MUST be derived from:

			configuration_snapshot.price_model

			External market data: FORBIDDEN
