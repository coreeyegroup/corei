PHASE D — STEP 3: RISK ENGINE (EXECUTION ENFORCEMENT LAYER)

1. PHASE IDENTITY LAYER
	1.1 Phase Name

		Phase D — Step 3: Risk Engine (Execution Enforcement Layer)

	1.2 Phase Role

		Deterministic enforcement layer that:

			consumes DecisionValidatedIntent
			enforces Phase B constraints
			applies multi-level risk controls
			produces RiskApprovedIntent

		This is the first enforcement gate in execution chain, aligned with macro ordering:
		TradeIntent → Risk → Policy → Execution

	1.3 Phase Objective

		Transform:

			DecisionValidatedIntent → RiskApprovedIntent

		Such that:

			all intents are risk-compliant
			capital allocation is bounded
			exposure is controlled
			system is protected from catastrophic failure
			output is deterministic and replay-safe

	1.4 Why This Phase Exists

		Without Risk Engine:

			unlimited scaling of high-confidence signals
			exposure accumulation across strategies
			CEIL capital contamination
			violation of Phase B constraint envelope
			non-reproducible execution decisions

		→ system-level failure

5. LOGIC / RULE ENGINE
	5.1 Rule Classes
		R1 — Input Validation
		R2 — Constraint Binding
		R3 — Exposure Evaluation
		R4 — Capital Evaluation
		R5 — Size Adjustment
		R6 — Risk Decision Assignment
		R7 — Output Construction

	5.2 Risk Validation Rules (MANDATORY)

		Check against:

			Position limits
			Strategy exposure
			Portfolio exposure
			Firm exposure
			Capital availability
			Drawdown limits

		Exposure Update Rule (MANDATORY):

			For sequential processing:

			exposure_state_current = initial snapshot

			FOR each approved intent:

				exposure_state_current += approved_size

			Subsequent intents MUST use updated exposure_state_current


		Directional Exposure Update (MANDATORY):

			IF direction == BUY:

				exposure_state_current += approved_size

			ELSE IF direction == SELL:

				exposure_state_current -= approved_size

			Constraint:

			exposure_state_current MUST NOT go below 0

			IF exposure_state_current < 0:
				→ HARD FAIL (invalid state)

	5.3 Capital Allocation Function
		approved_size = MIN(
			requested_size,
			position_limit_remaining,
			capital_remaining,
			exposure_remaining
		)

		Constraints:

			fixed-point arithmetic only
			overflow → REJECT
			underflow → 0


			capital_remaining

			WITH:

			IF origin_type == CORE:
				capital_remaining = core_capital_remaining
			ELSE:
				capital_remaining = external_capital_remaining

		IF capital_remaining < threshold:

			STOP all further approvals
			emit SYSTEM_RISK_EVENT

		Pre-Validation Rule (MANDATORY):

			IF any of the following:

				capital_remaining < 0
				exposure_remaining < 0
				position_limit_remaining < 0

			THEN:

				status = REJECTED
				approved_size = 0

				risk_flag = INVALID_STATE

	5.4 Decision Logic
		IF any hard constraint violated:
			status = REJECTED
			approved_size = 0

		ELSE IF partial constraint violation:
			status = REDUCED
			approved_size = bounded value

		ELSE:
			status = APPROVED
			approved_size = requested_size


		Constraint Classification (MANDATORY):

			constraints classified as:

			HARD_CONSTRAINTS = {
				drawdown_limit,
				firm_exposure_limit,
				invalid_state
			}

			SOFT_CONSTRAINTS = {
				position_limit,
				strategy_exposure,
				capital_limit
			}

			Precedence Rule:

			IF any HARD_CONSTRAINT violated:
				status = REJECTED
				approved_size = 0

			ELSE:
				approved_size = MIN(...)

				IF approved_size < requested_size:
					status = REDUCED
				ELSE:
					status = APPROVED

	5.5 Rule Execution Order (STRICT)
		Input Validation
		Constraint Binding
		Exposure Evaluation
		Capital Evaluation
		Size Computation
		Risk Decision Assignment
		Output Construction

		Constraint: no lower rule overrides higher rule

6. FLOW ARCHITECTURE
	6.0 Canonical Input Set (MANDATORY)
		canonical_input_set_D3 = {
			decision_validated_intent_stream,
			constraint_specification,
			portfolio_state_snapshot,
			configuration_snapshot,
			version_identifiers
		}

		Constraints:

			immutable
			complete
			hash-identifiable

	6.1 Input
		DecisionValidatedIntent (from Step 2)
		constraint_specification (Phase B)
		portfolio_state_snapshot (Phase C)

	6.2 Processing Flow
		DecisionValidatedIntent
			→ Risk Validation
			→ Exposure Check
			→ Capital Check
			→ Size Adjustment
			→ RiskDecision
			→ RiskApprovedIntent

		GLOBAL CAPITAL LOCK:

			FOR shared capital pool:

				process intents STRICTLY SEQUENTIAL

				parallelism FORBIDDEN


		Deterministic Capital Sequencing (MANDATORY):

			All intents MUST be processed in strict order:

			ordering_key = {
				event_time ASC
				origin_type (CORE=1, EXTERNAL=2)
				sequence_id ASC
			}

			Processing MUST be sequential:

			FOR intent IN ordered_intents:

				evaluate capital_remaining_current

				approved_size = f(...)


			Capital State Update Rule (MANDATORY):

				FOR intent IN ordered_intents:

					IF origin_type == CORE:

						approved_size = f(
							requested_size,
							position_limit_remaining,
							core_capital_remaining,
							exposure_remaining
						)

						core_capital_remaining -= approved_size

					ELSE:

						approved_size = f(
							requested_size,
							position_limit_remaining,
							external_capital_remaining,
							exposure_remaining
						)

						external_capital_remaining -= approved_size

	6.3 Output
		risk_approved_intent_stream = {
			intents: [
				{
		            risk_approved_intent_id
					decision_validated_intent_id
					risk_status
					approved_size
					risk_flags
					constraint_references
				}
			]
		}

		Risk Approved Intent Identity Rule (MANDATORY)

			risk_approved_intent_id MUST be computed as:

				HASH_v1(
					decision_validated_intent_id +
					risk_status +
					approved_size +
					ordered(risk_flags) +
					ordered(constraint_references)
				)

			Constraint:

				identical input → identical risk_approved_intent_id

	6.4 Flow Canonicalization Rule
		no external data
		no runtime dependency
		pure function of canonical_input_set_D3

8. CONTROL & CONSTRAINTS
	Hard Rules
		risk approval mandatory before policy
		no cross-capital usage
		deterministic output
		no hidden state

	Guardrails
		reject invalid intent
		reject constraint violation
		reject capital breach

	Invariants
		same input → same risk output
		no exposure breach
		capital always bounded

		I-GLOBAL-3: Capital MUST be consumed in deterministic sequence

	Numeric Boundaries:

		approved_size:

		min = 0
		max = min(capital_limit, position_limit)

		Edge Behavior:

		approved_size = 0 → status MUST be REJECTED
		approved_size < requested_size → REDUCED
		overflow → HARD FAIL

	Capital Isolation Invariant:

		core_capital_remaining MUST NEVER be affected by EXTERNAL intents

		external_capital_remaining MUST NEVER be affected by CORE intents

	Capital State Ownership Rule:

		There MUST NOT exist any global capital variable.

		All capital computations MUST use ONLY:

			core_capital_remaining
			external_capital_remaining

		Violation → HARD FAIL
