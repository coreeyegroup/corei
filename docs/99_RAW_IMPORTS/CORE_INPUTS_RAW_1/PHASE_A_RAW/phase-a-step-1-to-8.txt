						ELSE current_drawdown / peak_equity_reference

										exposure_vector_i < 0 → short exposure

				Step 3: Exposure Balance Score

					exposure_balance_score =
						1 - (max(E_cluster_k) / E_total)

					Constraint:
						E_total > 0
						IF E_total == 0 → exposure_balance_score = 1


				Step 4: Risk Level Computation

					risk_score =
						w1 * drawdown_ratio

					Constraints:
						w1 + w2 = 1
						fixed-point arithmetic only


				Step 5: Risk Level Classification

					risk_level =
						IF risk_score < R1 → LOW
						IF R1 ≤ risk_score < R2 → MEDIUM
						IF risk_score ≥ R2 → HIGH

						drawdown_breach:
							drawdown_state == CRITICAL

						exposure_breach:

		5.1 Core Allocation Formula

			Base Allocation Weight

				W_base = f(signal_strength)

			Risk-Adjusted Weight

				W_adj = W_base × Risk_Modifier

			Normalized Allocation

				W_norm = W_constrained / Σ(W_constrained across active strategies)

			Capital Assignment

				Capital_i = Total_Capital × W_norm_i

			Normalization Safety Rule

				Let:
					S = Σ(W_constrained across active strategies)

				IF S == 0:

					ALL W_norm_i = 0
					system MUST transition to ZERO_ALLOCATION state

				ELSE:

					W_norm_i = W_constrained_i / S

			Risk Modifier Constraint

				Risk_Modifier MUST be:

					deterministic
					monotonic decreasing with risk_factor
					bounded within [0,1]

				Defined in Risk Model (Step 4)

		5.2 Deterministic Rules

			Rule 1: Signal Dominance

				Higher signal_strength → strictly higher allocation weight

			Rule 2: Risk Suppression

				Higher risk_factor → reduces allocation weight

			Rule 3: Strategy Independence

				Each strategy evaluated independently before normalization

			Rule 4: Allocation Normalization

				Total allocation must equal 100% of capital_pool

			Rule 5: Minimum Viability Threshold

				Signals below threshold → allocation = 0

		5.3 Constraints

			No negative allocation
			No over-allocation (>100%)
			No allocation without decision validation

			Constraint Integration Rule (MANDATORY)

				Allocation constraints MUST be applied BEFORE normalization:

					W_adj_i → W_constrained_i

				Where:

					W_constrained_i = min(max(W_adj_i, W_min_i), W_max_i)

				Normalization MUST use:

					W_constrained_i (NOT W_adj_i)

				No iterative re-normalization allowed

	5. LOGIC / RULE ENGINE
		5.1 Canonical Input Set (MANDATORY)
			canonical_input_set = {

			Constraints:

			derivation function MUST be deterministic and fully specified

		External Feedback Exclusion (MANDATORY)

			Learning Model MUST use ONLY:

			External trade outcomes (CEIL):

				MUST NOT be included in:
					performance_snapshot_set
					learning_dataset
					parameter updates

			Constraint:

				External trades MUST NOT influence model evolution

		5.2 Evaluation Rules
			R1: Deterministic Metric Computation

				All metrics MUST be computed using:

				fixed formulas
				fixed time windows
				fixed-point arithmetic

				Examples:

				Sharpe
				max drawdown
				win-rate
				return variance

			R2: Dataset Selection Rule

				Learning dataset MUST satisfy:

				fixed time window
				no missing data
				deterministic inclusion criteria

				If violation:
				→ learning cycle MUST NOT execute

				Deterministic Inclusion Definition (MANDATORY)

					learning_dataset MUST be constructed using:

					fixed time_window
					fixed strategy set
					fixed completeness requirement

					Inclusion Rule:

					include ALL performance_snapshot entries WHERE:

					timestamp ∈ time_window
					strategy_id ∈ predefined strategy_set
					data completeness = TRUE

					No conditional or adaptive filtering allowed

				data completeness = TRUE IF AND ONLY IF:

						all required fields present
						AND no null values
						AND timestamps fully aligned within time_window

						Else:
						data completeness = FALSE

			R3: Parameter Sensitivity Evaluation

				Each parameter MUST be evaluated independently:

				Δperformance = f(parameter_variation)

				Constraints:

				variation steps predefined
				evaluation grid fixed
				no stochastic search

				Parameter Evaluation Grid (MANDATORY)

					Each parameter MUST define:

					min_value
					max_value
					step_size

					Evaluation Set:

					parameter_values = {min_value + k * step_size}

					Constraints:

					k MUST be integer
					range MUST be finite
					evaluation order MUST be ascending

					No stochastic variation allowed

				IF (max_value - min_value) is not divisible by step_size:

					parameter_values MUST include only values ≤ max_value

					No extension beyond max_value allowed


				All parameter updates MUST be:

					computed independently
					AND applied simultaneously

					No sequential dependency allowed


			R4: Update Eligibility Rule

				Parameter update allowed ONLY IF:

				improvement_metric ≥ threshold_min
				AND
				risk_metric ≤ threshold_max

				Else:
				→ parameter remains unchanged

				Precedence Rule (MANDATORY)

					Evaluation order MUST be:

					1 risk_metric validation
					2 improvement_metric validation

					Constraint:

					IF risk_metric > threshold_max
					→ update MUST be rejected

					improvement condition MUST NOT override risk constraint

			R5: Update Magnitude Constraint
				|new_value - old_value| ≤ delta_max

				Edge:

				if exceeded → clamp to delta_max
				if undefined → reject update

			R6: Version Generation Rule

				New version MUST be created ONLY IF:

				at least one parameter updated
				all updates validated

				Else:
				→ no new version

				version_id MUST be computed from:

					ordered parameter_update_set (by parameter_id)
					performance_snapshot_set hash
					configuration_snapshot hash
					version_identifiers
					learning_dataset hash

					Ordering MUST be deterministic

			All inputs to version_id MUST be serialized in deterministic order:

					1 parameter_update_set (sorted by parameter_id)
					2 performance_snapshot_set hash
					3 configuration_snapshot hash
					4 learning_dataset hash
					5 version_identifiers

					No permutation allowed

			R7: Deterministic Ordering

				All updates MUST be ordered by:

				parameter_id (lexicographic)
				magnitude (descending)

				Precondition (MANDATORY)

					update_magnitude MUST be computed BEFORE ordering

					Constraint:

					ordering MUST depend only on:

					parameter_id
					update_magnitude (deterministically computed)

					No runtime-dependent values allowed

		5.3 RULE EXECUTION ORDER (STRICT)
			Input validation
			Dataset validation
			Metric computation
			Parameter sensitivity evaluation
			Update eligibility check
			Update magnitude enforcement
			Version generation
			Hash computation

			No deviation allowed.
