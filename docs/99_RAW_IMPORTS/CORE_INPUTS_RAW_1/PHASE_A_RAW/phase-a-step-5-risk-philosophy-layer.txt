	5. LOGIC / RULE ENGINE (CORE)
		5.1 Risk Hierarchy Rule (STRICT)

				Firm Risk > Portfolio Risk > Strategy Risk > Trade Risk

			Constraint:
			Lower layer MUST NOT override higher layer.

		5.2 Capital Preservation Rule

			Primary objective = survival over profit

			Risk decisions MUST prioritize:
				drawdown containment
				capital protection
				exposure stability

		5.3 Exposure Philosophy

			Exposure MUST be:
				intentional
				bounded (logically)
				diversified

			Rules:
				No uncontrolled directional accumulation
				No hidden correlated exposure
				Exposure must reflect decision confidence + system state

			Exposure Normalization Constraints

				Let:

					E_total = total exposure magnitude
					E_cluster = exposure per correlation cluster

				Constraints:

					E_total ≤ E_max_class
					E_cluster ≤ cluster_limit

					exposure_balance_score MUST be computed deterministically

				Violation → constraint_flag MUST be set

		5.4 Drawdown Response Model

			Drawdown States:
				Normal
				Elevated
				Critical

			Behavioral Philosophy:
				As drawdown increases:
					risk appetite decreases
					exposure must contract
					aggressiveness must reduce

			Drawdown Classification Function

				drawdown_ratio =
					current_drawdown / peak_equity_reference

				drawdown_state =
					IF drawdown_ratio < T1 → NORMAL
					IF T1 ≤ drawdown_ratio < T2 → ELEVATED
					IF drawdown_ratio ≥ T2 → CRITICAL

				Constraints:

					T1, T2 MUST be globally defined constants
					Classification MUST be deterministic

			current_drawdown =
				max(realized_drawdown, unrealized_drawdown)

		5.5 Risk Consistency Rule

			Same conditions → same risk interpretation
			No discretionary overrides at logic level

		5.6 Strategy Risk Independence Rule

			Strategies do NOT manage their own risk globally
			Risk is applied consistently across all strategies

		5.7 Risk–Decision Alignment Rule

			Risk Philosophy MUST NOT:
				change decision logic

			Risk Philosophy MUST:
				constrain downstream execution behavior

			Risk Evaluation Function (MANDATORY)

				Risk_Context = f(
					trade_intent_snapshot,
					execution_instruction_snapshot,
					portfolio_state_snapshot,
					configuration_snapshot
				)

				Constraints:

					Function MUST be:
						deterministic
						order-independent
						replayable

					Same input → identical Risk_Context output

					No implicit logic allowed

			Global Numeric Model (MANDATORY)

				ALL computations in this phase MUST use fixed-point arithmetic:

					value = integer / 10^6

				Applies to:

					drawdown_ratio
					E_total
					E_cluster_k
					exposure_balance_score
					risk_score
					all intermediate computations

				Constraint:

					Floating-point arithmetic is strictly forbidden

			Risk Computation Model (MANDATORY — FULL DEFINITION)

				Step 1: Drawdown Evaluation

					drawdown_ratio =
						IF peak_equity_reference == 0 → 0
						ELSE current_drawdown / peak_equity_reference


				Step 2: Exposure Aggregation

							Exposure Primitive Definition (MANDATORY)

								exposure_vector_i:

									scalar signed exposure value per instrument

									where:

										exposure_vector_i > 0 → long exposure
										exposure_vector_i < 0 → short exposure

								total_exposure_vector:

									ordered deterministic list of exposure_vector_i across all instruments

							Constraint:

								ordering MUST be deterministic and stable across identical inputs

						E_total = Σ |exposure_vector_i|

							where:
								exposure_vector_i ∈ total_exposure_vector

						E_cluster_k = Σ exposure_i for cluster k

				Step 3: Exposure Balance Score

					exposure_balance_score =
						1 - (max(E_cluster_k) / E_total)

					Constraint:
						E_total > 0
						IF E_total == 0 → exposure_balance_score = 1


				Step 4: Risk Level Computation

					risk_score =
						w1 * drawdown_ratio
					  + w2 * (1 - exposure_balance_score)

					Constraints:
						w1 + w2 = 1
						fixed-point arithmetic only


				Step 5: Risk Level Classification

					risk_level =
						IF risk_score < R1 → LOW
						IF R1 ≤ risk_score < R2 → MEDIUM
						IF risk_score ≥ R2 → HIGH


				Step 6: Constraint Flag Generation

					constraint_flags = {

						drawdown_breach:
							drawdown_state == CRITICAL

						exposure_breach:
							E_total > E_max_class

						cluster_concentration_breach:
							any(E_cluster_k > cluster_limit)

					}


				Step 7: Precedence Enforcement (STRICT)

					Apply in order:

						1. Firm-level override
						2. Drawdown constraints
						3. Exposure constraints
						4. Strategy-level
						5. Trade-level

					Constraint:
						Once constraint activated → lower layers cannot override

			Global Evaluation Order (MANDATORY)

				Risk evaluation MUST follow strict sequence:

					1. Input Validation
					2. Risk Computation
					3. Constraint Flag Generation
					4. Invariant Validation
					5. Output Emission

				Constraint:

					If invariant violation occurs at step 4:

						Risk_Context MUST NOT be generated

						Constraint flags MAY still be computed but MUST NOT be emitted

			Input Validation Rules

				Reject input if:

					missing required field
					invalid domain value
					inconsistent timestamps
					incomplete snapshot

			Numeric Safety Constraints (MANDATORY)

				1. Division Safety

					IF denominator == 0:
						computation MUST fallback to defined default

				2. Bounds Enforcement

					0 ≤ drawdown_ratio ≤ 1
					0 ≤ exposure_balance_score ≤ 1
					0 ≤ risk_score ≤ 1

				3. Constant Constraints

					0 < T1 < T2 < 1
					0 < R1 < R2 < 1
					E_max_class > 0
					cluster_limit > 0

				Violation → system invalid

		External Input Neutrality Constraint

			Risk Philosophy MUST be defined independent of trade origin:

				CORE and EXTERNAL trades MUST follow same philosophy

			However:

				Risk Philosophy MUST NOT differentiate behavior
				based on source of trade intent

			Source-based control is enforced in Phase D Risk Engine only

		IF size > capacity_limit:
			size = capacity_limit

		IF capacity_limit == 0:
			RETURN NoTradeIntent

							portfolio_state.timestamp
						)

				Explanation:

					evaluation_time represents the ONLY valid logical time
					at which risk evaluation is performed.

					It ensures:
						all inputs are aligned to a single deterministic time reference


				--------------------------------------------------

				TIME SOURCE RULES (STRICT)

				1. trade_intent.event_time
					→ inherited from Decision Engine (Step 3)

				2. execution_instruction.decision_time
					→ inherited from Execution Behavior (Step 4)

				3. portfolio_state.timestamp
					→ must represent state at exact logical time


				Constraint:

					All time values MUST be:
						deterministic
						comparable
						derived from upstream phases

					Manual or arbitrary time assignment is strictly forbidden


				--------------------------------------------------

				TIME ALIGNMENT RULE (CRITICAL)

					Deterministic Time Alignment Rule (MANDATORY)

						For each input:

							select value with:

								1. timestamp ≤ evaluation_time
								2. maximum timestamp among valid candidates

						If multiple candidates share identical timestamp:

							select based on deterministic hash ordering

						Constraint:

							Selection MUST produce identical result for identical inputs

				--------------------------------------------------

				STALENESS VALIDATION (MANDATORY)

				For each input:

					input_time =
						corresponding timestamp of each input entity

				Constraint:

					Δt_input ≤ staleness_limit

				If violated:

					→ canonical_input_set is INVALID
					→ Risk_Context MUST NOT be generated

				Δt_input =
					evaluation_time - input_time
				--------------------------------------------------

				ORDERING RULE (DETERMINISTIC)

				If multiple evaluations occur:

					evaluations MUST be ordered strictly by:

						1. evaluation_time
						2. input_hash_reference

				Constraint:

					identical inputs → identical ordering


				--------------------------------------------------

				REPLAY CONSISTENCY RULE

				Given identical canonical_input_set:

					evaluation_time MUST be identical
					output MUST be identical

				Any deviation:

					→ system invalid
