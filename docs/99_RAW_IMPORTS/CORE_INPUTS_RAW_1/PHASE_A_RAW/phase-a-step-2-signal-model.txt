	5. LOGIC / RULE ENGINE
		5.1 Signal Function
			Signal = f(Market State, Strategy Config, Internal Logic)

		5.2 Determinism Rules
			Same input → identical signal (bit-level)
			No hidden randomness
			No floating-point arithmetic allowed

		5.3 Arithmetic Model (CRITICAL)
			ALL computations → fixed-point

			value = integer / 10^6

		5.4 Indicator Determinism
			Each indicator MUST define:
				formula
				window
				computation order
				rounding rules

			All inputs used in indicator computation MUST be included in input_snapshot

		5.5 Market State Dependency
			Fully aligned to event_time
			No partial inputs
			Missing required input → NO SIGNAL

		5.6 Numeric Safety Rules

			All fixed-point computations MUST define:

				Maximum value bounds
				Minimum value bounds

			If overflow or underflow occurs:
				→ Computation MUST fail
				→ Signal MUST NOT be generated

			Silent numeric clipping is strictly forbidden

	7. PIPELINE STRUCTURE
		Pipeline defines operational lifecycle, not logical transformation

		Signal Lifecycle Pipeline
			Generate → Validate → Emit → Active → Expire → Archive

		Transition Rules
			Generate → only if valid inputs
			Emit → only if meaningful change
			Expire → deterministic

		Signal is ACTIVE if:
			current_time < expiry_time

		Signal is EXPIRED if:
			current_time ≥ expiry_time

	10. ENCODING & HASHING MODEL (CRITICAL)

	11. SIGNAL SEMANTICS
		Signals represent:

			Intent, not execution

		They DO NOT:
			Execute trades
			Allocate capital
			Apply risk

		They ONLY express:
			Directional intent + conviction + time validity

		External Influence Constraint (MANDATORY)

			Signals MUST be generated ONLY from:

				strategy logic
				market state
				configuration

			Signals MUST NOT incorporate:

				external trade intents
				external model outputs
				CEIL-derived data

			Any such dependency → signal invalid


	12. TIME MODEL

		processing_time MUST be system ingestion time in UTC

		Dual Time System
			event_time      → logical (decision basis)
			processing_time → system (non-decision)

		Constraints
			All logic must use event_time
			Must satisfy latency bound:
				processing_time - event_time ≤ allowed_limit

		Violation Rule

			If processing_time - event_time > allowed_limit:
				→ Signal MUST be rejected (invalid)

			Event-time violation is a hard failure, not a warning

		event_time MUST be derived from input snapshot:

			event_time = max(timestamp of all inputs used)

		Manual assignment is strictly forbidden

		Deterministic Ordering Rule

			Signals MUST be ordered by:

				1. event_time
				2. strategy_id (lexicographic)
				3. signal_id

			This ordering MUST be used in:
				emission
				density control
				replay

	13. SIGNAL STRENGTH MODEL
		Dual Strength
			local  → strategy internal
			global → calibrated (used downstream)

		Constraints
			Monotonic
			Globally validated
			Cannot be self-approved

		Calibration Validation Rules

			Calibration MUST satisfy:

				Statistical consistency with historical outcomes
				Distribution alignment across strategies

			Validation Metrics (MANDATORY):
				Calibration error bounds
				Distribution deviation thresholds

			If calibration fails validation:
				→ Strategy signals MUST be rejected

			Calibration MUST be based on historical out-of-sample data

		signal_strength_local ∈ [0,1]
		signal_strength_global ∈ [0,1]

		Values outside range → invalid signal

	14. VALIDITY & DECAY MODEL
		Validity
			validity_window ∈ bounded class
			expiry_time = event_time + validity_window

			validity_class ∈ {ultra_short, short, medium, long}

		Decay
		Allowed:
			linear_standard
			exponential_standard

		Constraints:
			Monotonic
			Standardized parameters
			No custom decay shapes

		Parameter Constraints

			Each decay type MUST define bounded parameters

			Example:
				exponential_standard:
					lambda ∈ [λ_min, λ_max]

			Parameter values outside bounds → invalid signal

		Validity Bounds Enforcement

			validity_window MUST fall within globally defined numeric bounds

			If validity_window outside allowed range:
				→ Signal MUST be rejected


	15. INPUT SNAPSHOT MODEL
		Snapshot Rules
			Immutable
			Minimal
			Deterministic

		Hash
			input_snapshot_hash = HASH(CBE(snapshot))

		Freshness Constraint
			All inputs must satisfy global staleness limits

		Completeness Rule

			Input snapshot MUST include ALL inputs used in signal computation

			Validation:
				If any required input is missing:
					→ Signal MUST NOT be generated

			Partial snapshot usage is strictly forbidden

		Freshness Enforcement

			Global staleness limits MUST be enforced strictly

			If any input exceeds allowed staleness:
				→ Signal MUST be rejected

		Canonical Snapshot Rule

			Input snapshot MUST contain EXACTLY the inputs used in signal computation

			AND MUST NOT contain:
				unused fields
				extra metadata
				derived values not used in computation

			If snapshot is not exact:
				→ Signal MUST be rejected

	17. SIGNAL EMISSION MODEL
		Constraints
			emission_frequency defined
			system_max_rate enforced

		Anti-Oscillation
			hysteresis
			minimum persistence duration

		Density Control
			max_signals_per_instrument_per_window

		Duplicate Handling Rule

			Signal identity is defined strictly by signal_id

		Cases:
			1. Same signal_id + identical payload
				→ Ignore (idempotent)

			2. Same signal_id + different payload
				→ HARD ERROR (system violation)

		Strategies MUST NOT emit duplicate signals

		Density Enforcement:

			If signal count exceeds max_signals_per_instrument_per_window:
				→ Excess signals MUST be rejected

			System-level enforcement is mandatory

		Emission requires:

			|Δsignal_strength| > threshold + hysteresis_margin
			AND persistence_duration ≥ min_duration

			threshold, hysteresis_margin, min_duration MUST be defined in strategy configuration

		Density Selection Rule

			If signal count exceeds limit:

				signals MUST be sorted by:

					1. event_time (ascending)
					2. signal_strength_global (descending)
					3. strategy_id (lexicographic)

				excess signals MUST be rejected based on this order
