	1. PHASE IDENTITY LAYER

		1.1 Phase Name

			Phase A — Step 7: Portfolio Model

		1.2 Phase Role

			Defines the deterministic structure, composition, and behavior of the portfolio as the aggregation layer above capital allocation and below system-level execution.

		1.3 Phase Objective

			To construct a fully deterministic, multi-strategy, multi-asset portfolio structure that transforms allocated capital (Step 5) and approved trade intents (Step 6) into a coherent exposure system.

		1.4 Why This Phase Exists

			Prevents:

				uncontrolled exposure aggregation
				hidden correlation risks
				non-deterministic portfolio composition
				capital fragmentation across strategies

			Strategy Allocation Unit

				strategy_exposure_vector

			Exposure Unit

				asset_id
				direction (long/short/neutral)
				notional_exposure
				normalized_weight

				Exposure Computation Definition (MANDATORY)

					strategy_exposure(asset_id) MUST be defined as:

						signed_notional_exposure

					Where:

						signed_notional_exposure =
							+notional_exposure  (if direction = long)
							−notional_exposure  (if direction = short)
							0                   (if direction = neutral)

					net_exposure(asset_id) = Σ(signed_notional_exposure across strategies)

			Asset Bucket

				asset_class
				instruments_set
				bucket_exposure

				Asset Bucket Mapping Rule (MANDATORY)

					asset_id MUST map to:

						asset_class (bucket)

					Mapping MUST be provided via:

						asset_to_bucket_mapping (from canonical_input_set)

					Each asset MUST map to exactly ONE bucket

			Correlation Cluster

				cluster_id
				member_assets
				aggregate_exposure

				Correlation Cluster Mapping Rule (MANDATORY)

					cluster_id MUST be derived from:

						asset_id → cluster_id (predefined mapping)

					Mapping MUST come from:

						configuration_snapshot

					Each asset MUST map to exactly one cluster

			Portfolio State Snapshot

				timestamp
				portfolio_exposure_vector
				concentration_metrics
				diversification_score

		4.3 Relationships

			Portfolio → contains → Strategy Allocation Units

	5. LOGIC / RULE ENGINE

		Deterministic Strategy Ordering (MANDATORY)

			All strategies MUST be processed in:

				strategy_id (lexicographic ascending)

			Applies to:

				extraction
				aggregation
				normalization

		Deterministic Asset Ordering (MANDATORY)

			All asset-level operations MUST follow:

				asset_id (lexicographic ascending)

			Applies to:

				exposure aggregation
				bucket mapping
				cluster mapping
				output generation

			Violation if:

				any asset iteration is unordered

		5.1 Rules

			R1: Portfolio Composition Rule

				Portfolio = deterministic aggregation of all strategy exposures

			R2: Exposure Normalization Rule

				All exposures must be normalized relative to total allocated capital

				R2.1 Normalization Formula (MANDATORY)

					Let:

						E_i = net_exposure for asset i
						C_total = total_allocated_capital

					Normalized Exposure:

						W_i = E_i / C_total

					Constraint:

						C_total > 0

					IF C_total == 0:

						ALL W_i = 0
						system MUST enter ZERO_PORTFOLIO_STATE

			R3: Aggregation Rule

				For each asset:

					net_exposure(asset) = Σ(strategy_exposure(asset))

			R4: Diversification Rule

				Portfolio must maintain distribution across:

					asset buckets
					correlation clusters

			R5: Concentration Rule

				No single:

					strategy
					asset
					cluster

					may dominate portfolio beyond threshold defined in configuration_snapshot


		5.2 Conditions

			Only approved strategies (Step 6) enter portfolio
			Only allocated capital (Step 5) contributes

			All exposures must be:

				finite
				signed
				normalized

			Asset Definition Enforcement (MANDATORY)

				All asset_id in:

					exposure_unit
					asset_to_bucket_mapping
					asset_to_cluster_mapping

				MUST exist in:

					asset_definition_set

				Violation → REJECT INPUT

			configuration_snapshot MUST include:

				strategy_threshold_map:
					strategy_id → max_weight

				asset_threshold_map:
					asset_id → max_weight

				cluster_threshold_map:
					cluster_id → max_weight

				All thresholds MUST be:

					numeric
					finite
					≥ 0


		5.3 Decision Logic

			Step-by-step:

				Collect strategy allocation units
				Extract exposure vectors
				Normalize exposures
				Aggregate by asset

					no implicit derivation allowed

					Mapping Completeness and Uniqueness (MANDATORY)

							exactly one bucket mapping MUST exist
							exactly one cluster mapping MUST exist

							asset_id → multiple buckets → INVALID
							asset_id → multiple clusters → INVALID

		External Exposure Exclusion (MANDATORY)

				CORE trade intents
