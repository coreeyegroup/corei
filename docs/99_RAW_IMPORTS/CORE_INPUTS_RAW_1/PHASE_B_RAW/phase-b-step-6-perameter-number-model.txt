5. LOGIC / RULE ENGINE
	5.1 Canonical Input Set

	5.2 Fixed-Point Arithmetic Rules (MANDATORY)
		Representation
			value = integer / 10^6

		Addition
			C_fp = A_fp + B_fp

		Multiplication
			C_fp = (A_fp * B_fp) / scale

		(using integer division with rounding)

		Division
			C_fp = (A_fp * scale) / B_fp

		Constraint:

			division by zero → HARD FAIL

		MANDATORY EXECUTION STANDARD:

			All arithmetic MUST follow EXACT sequence:

			1. Perform operation in INT128 space
			2. Apply scaling (if required)
			3. Apply ROUND_HALF_UP
			4. Cast to INT64

			Constraint:

			Intermediate representation MUST be INT128

			Violation → HARD FAIL

		INTEGER DIVISION STANDARD (MANDATORY):

			All division MUST follow:

			DIV_FP(A, B):

			1. numerator = A * scale
			2. quotient = numerator / B  (INT128 division)
			3. remainder = numerator % B

			4. IF |remainder * 2| ≥ |B|
				  quotient = quotient + sign(A/B)

			5. result_fp = quotient

			Constraint:

			- rounding MUST be symmetric around zero
			- behavior MUST be identical across platforms

		SIGN FUNCTION (MANDATORY):

			sign(x) = {
				+1 if x > 0
				 0 if x == 0
				-1 if x < 0
			}

			For division:

			sign(A/B) MUST be computed as:

			sign(A) * sign(B)

			Constraint:

			No direct division-based sign evaluation allowed

	5.3 Rounding Standard (GLOBAL)

		ROUND_HALF_UP (MANDATORY)

			fraction ≥ 0.5 → round up
			fraction < 0.5 → round down

		Constraint:

			truncation forbidden

	5.4 Overflow / Underflow Rules
		Overflow

		If:

			result_fp > MAX_INT64

			→ HARD FAIL

		UNDERFLOW DEFINITION:

			IF |value_fp| < 1 (after scaling, before rounding)
			→ value_fp = 0

		PRE-OPERATION OVERFLOW CHECK (MANDATORY):

			Before multiplication:

			IF |A_fp| > MAX_INT64 / |B_fp|
			→ HARD FAIL

			No operation may execute without pre-check

		SIGNED OVERFLOW (MANDATORY):

			Overflow MUST be evaluated on absolute value:

			|value_fp| > MAX_INT64 → HARD FAIL

			Sign MUST be preserved until failure

		OVERFLOW CHECK COVERAGE (MANDATORY):

			Addition:
			IF (A_fp > 0 AND B_fp > MAX - A_fp) → FAIL
			IF (A_fp < 0 AND B_fp < MIN - A_fp) → FAIL

			Division:
			IF A_fp == MIN_INT64 AND B_fp == -1 → FAIL

		NUMERIC LIMIT CONSTANTS (MANDATORY):

			MAX_INT64 = 9223372036854775807
			MIN_INT64 = -9223372036854775808

			Constraint:

			All systems MUST use these exact values

			No platform-dependent limits allowed

	5.5 Numeric Domain Enforcement

		For each parameter:

			IF value_fp < min_value_fp → apply edge_behavior
			IF value_fp > max_value_fp → apply edge_behavior

		Edge Behavior
			CLAMP → set to boundary
			REJECT → fail evaluation
			SATURATE → hold max

		EDGE BEHAVIOR PRECEDENCE (STRICT):

			1. REJECT (highest priority)
			2. CLAMP
			3. SATURATE

			Constraint:

			If multiple behaviors applicable → select highest precedence

			No ambiguity allowed

	5.6 Deterministic Ordering Rule

		All numeric operations MUST be executed in:

			parameter_id ASC
			operation_id ASC

		Constraint:

			no unordered computation allowed

		OPERATION SEQUENCE ORDER (MANDATORY):

			operation_sequence MUST be ordered by:

			1. evaluation_unit_id ASC
			2. parameter_id ASC
			3. operation_id ASC

			Constraint:

			hashing MUST use this exact ordering

	5.7 Numeric Consistency Rule

		All parameters shared across:

			Decision Engine
			Execution Behavior
			Risk Philosophy

		MUST:

			use same scale
			use same rounding
			use same bounds

		NUMERIC CONTRACT (MANDATORY):

			All phases MUST enforce:

			scale = 10^6
			rounding = ROUND_HALF_UP
			overflow_behavior = HARD_FAIL
			execution_order = identical
