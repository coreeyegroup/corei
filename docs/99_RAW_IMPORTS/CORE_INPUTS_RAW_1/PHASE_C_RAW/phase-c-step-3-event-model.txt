4. DOMAIN MODEL DEFINITION
	4.1 Core Entity — Event
		event = {
			event_id
			event_type
			event_time
			partition_key
			entity_id
			signal_id
			payload
			dependency_set
			validation_hash
			lineage_hash
			version_identifiers
		}

		partition_key = {
				instrument
				entity_id
			}

			Constraint:

			- MUST be derived ONLY from canonical_input_set_C
			- MUST be deterministic
			- MUST match Step 2 routing function

		partition_id = HASH_v1(partition_key) mod N_partitions

			Constraint:

			- MUST match Step 2 partition routing function
			- MUST be deterministic
			- MUST use SHA-256

		event_time derivation:

			SIGNAL:
				signal_snapshot.timestamp

			DECISION:
				decision_time

			EXECUTION:
				execution_instruction_time

			CONSTRAINT:
				constraint_snapshot_time

			SYSTEM:
				configuration_snapshot.reference_time

			Constraint:

			- MUST be derived ONLY from canonical_input_set_C
			- system clock forbidden

			EVENT TIME SOURCE RULE:

				event_time MUST be derived ONLY from event_type mapping.

				Multiple derivation rules are FORBIDDEN.

				Violation → HARD FAIL

			signal_payload = {
					signal_id: string (non-null, globally unique)
					strategy_id
					instrument
					signal_strength
				}

		ExecutionEventBus (NEW)

				ExecutionEventBus = {
					topic: execution_order_stream
					topic: oms_request_stream
					topic: ems_instruction_stream
					topic: broker_event_stream
				}

				Constraints:

				- MUST preserve ordering from Phase D
				- MUST be partitioned deterministically:

					partition_key = order_id

				- MUST guarantee:

					ordering_key = {
						event_time ASC
						sequence_id ASC
					}

				- MUST support replay (event sourcing)

				Violation → REPLAY FAILURE

		GLOBAL EVENT IMMUTABILITY GUARD

			FOR every event transition across phases:

				HASH_v1(before_payload) == HASH_v1(after_payload)

			If mismatch:
				→ HARD FAIL

			Applies to:
			- Phase D transformations
			- OMS/EMS transport layer


	4.2 Event Identity Rule (MANDATORY)
		event_id = HASH_v1(canonical_event_payload)

		Constraints:

		deterministic
		globally unique
		identical payload → identical event_id

		(Aligned with Step 2 infra)

		HASH CANONICALIZATION RULE (MANDATORY):

			event_id = HASH_v1(canonical_event_payload)

			Constraint:

			- payload MUST NOT be hashed independently
			- canonical_event_payload is the ONLY valid hashing input
			- any mismatch → HARD REJECT

		ExecutionChannel Contract (MANDATORY)

			- routing_target MUST be deterministic function of:
				instrument + execution_type

			- channel MUST preserve ordering:
				same partition → same channel

			- channel failure:
				→ deterministic retry via retry_policy

			- no dynamic routing allowed


	4.3 Canonical Payload Definition
		canonical_event_payload = {
			event_type
			event_time
			partition_key
			entity_id

		}

		Serialization:

	4.4 Event Taxonomy (LOCKED)
			event_type ∈ {
				SIGNAL
				DECISION
				EXECUTION
				CONSTRAINT
				SYSTEM
			}

			Event Type Roles
			Type	Source	Role
			SIGNAL	Phase A	raw signal emission
			DECISION	Phase A	trade intent
			EXECUTION	Phase C/D	execution instruction
			CONSTRAINT	Phase B	constraint validation signal
			SYSTEM	Phase C	infra-level control

		4.5 Payload Schema Contracts (MANDATORY)

			Each event_type MUST define:

			payload_schema = {
				field_name
				data_type
				min_value
				max_value
				nullability
				invalid_condition
			}

			Example — DECISION Event
			decision_payload = {
				signal_id: string (non-null)
				strategy_id: string (non-null)
				instrument: string (non-null)
				direction: enum {BUY, SELL}
				size: fixed-point (min > 0)
				confidence: fixed-point (0 → 1)
			}

			Schema Enforcement Rules

			Reject event if:

			missing field
			extra field
			type mismatch
			out-of-bound value

			Numeric fields MUST specify:

				- representation: fixed-point (integer / 10^6)
				- min_value
				- max_value
				- overflow behavior → REJECT
				- underflow → zero

				Constraint:

				- schema without numeric bounds → INVALID

			TRACEABILITY ROOT RULE (MANDATORY)

				signal_id MUST originate ONLY from SIGNAL event.

				All downstream events MUST preserve:

					signal_id = parent.signal_id

				Violation → HARD FAIL

	4.6 Dependency Model (CRITICAL)
		dependency_set = {
			event_id_1,
			event_id_2,
			...
		}

		Constraints:

		MUST reference existing events
		MUST NOT form cycles
		Dependency Rule
		∀ dependency d:
			d.event_time ≤ event.event_time
		Cross-Partition Guarantee

		If dependency crosses partition:

		orchestrator MUST enforce ordering
		replay MUST preserve dependency resolution

		dependency_set MUST be:

			- sorted by event_id ASC

			Dependency Resolution Rule:

			For equal event_time:

				resolve using:
					1. dependency depth
					2. event_id ASC

			Cycle detection → HARD FAIL

		dependency_depth(event):

			= max(depth of all dependencies) + 1

			Base:

			event with no dependencies → depth = 0

			Constraint:

			- MUST be computed deterministically
			- MUST be acyclic

	4.7 Event Lifecycle Model
			CREATED
			→ VALIDATED
			→ ORDERED
			→ APPENDED
			→ PROCESSED
			→ SNAPSHOT_APPLIED
			→ FINALIZED
			Lifecycle Constraints
			no skipping states
			no backward transitions
			idempotent transitions

		Allowed transitions ONLY:

			CREATED → VALIDATED
			VALIDATED → ORDERED
			ORDERED → APPENDED
			APPENDED → PROCESSED
			PROCESSED → SNAPSHOT_APPLIED
			SNAPSHOT_APPLIED → FINALIZED

			Else → REJECT

	4.8 Event Ordering Model

		Global ordering:

			1. event_time ASC
			2. partition_id ASC
			3. event_id ASC

			(Aligned with Step 2 global ordering)

		GLOBAL DEPENDENCY ORDER RULE:

			If event_B depends on event_A:

				event_A MUST appear before event_B
				in global ordering

			Violation → HARD FAIL
