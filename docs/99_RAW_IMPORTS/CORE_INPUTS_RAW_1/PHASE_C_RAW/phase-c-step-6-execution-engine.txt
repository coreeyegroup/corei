5. LOGIC / RULE ENGINE
	5.1 Rule Set
		R1 — Execution Order Rule

			Execution MUST follow:

				execution_plan.ordered_tasks

			NO deviation allowed

		R2 — Dependency Enforcement Rule

			Task executes ONLY IF:

			∀ dependency_task ∈ dependency_set:
				dependency_task.status = COMPLETED

		R3 — Partition Ordering Rule

			Within same partition:

				strict sequential execution

		R4 — Idempotency Rule

			If task already executed:

				skip execution
				verify output_hash matches

			Mismatch → HARD FAIL

		R5 — Deterministic Function Rule

			Each service execution:

				output = deterministic_function(input)

			Constraints:

				pure function
				no external input
				fixed-point numeric

				R5.1 — Execution Function Definition Rule

					execute(task):

						input = canonical_event_payload(task.event_id)

						deterministic_function =
							deterministic_function_reference(task.service_id)

						output = deterministic_function(input)

						Constraints:

							- MUST be pure function
							- MUST use ONLY canonical input
							- MUST NOT access external state
							- MUST produce schema-bound output
							- MUST be deterministic (same input → same output)

						return output

		R6 — State Transition Trigger Rule

			After execution:

				State(t+1) = Apply(Event, Output)

			ONLY via Step 4 engine

		R7 — Replay Rule

			Replay MUST reconstruct:

				identical execution_plan
				identical task sequence
				identical outputs

		RULE PRECEDENCE (STRICT)
			Dependency (R2)
			Partition Ordering (R3)
			Execution Order (R1)
			Idempotency (R4)
			Execution (R5)
			State Trigger (R6)

		R8 — Execution Isolation Rule

			For each task_id:

				execution MUST satisfy:

					exactly-once execution guarantee

			Implementation:

				execution_lock = HASH_v1(task_id)

				Only one execution instance allowed per task_id

			Violation → HARD FAIL

		R9 — Output-State Contract Rule

			TaskExecutionResult.output_payload MUST:

				match state_transition_schema

			Validation required BEFORE state transition

			Mismatch → REJECT

		Execution Resolution Matrix (STRICT):

			IF dependency NOT satisfied:
				BLOCK

			ELSE IF partition order violated:
				BLOCK

			ELSE IF task already executed:

				VERIFY idempotency

				IF output_hash mismatch:
					HARD FAIL

				ELSE:
					SKIP

			ELSE:
				EXECUTE
