5. LOGIC / RULE ENGINE
	5.1 Rules
		R1 — Checkpoint Creation Rule

			Checkpoint created when:

				event_count % interval == 0
				OR
				event_time crosses time_window

			TIME WINDOW DEFINITION (MANDATORY):

				time_window = fixed-size event_time bucket

				window_id = floor(event_time / window_size)

				Checkpoint MUST trigger ONLY when:
				window_id changes

				Rolling time windows are FORBIDDEN
				System clock usage is FORBIDDEN

		R2 — Checkpoint Hash Rule
			checkpoint_hash = HASH_v1(
				checkpoint_id +
				event_offset_map +
				state_hash_reference +
				snapshot_id
			)

		R3 — Recovery Rule
			recover(system_state, event_log):

				1. locate latest valid checkpoint
				2. restore snapshot
				3. resume event processing from checkpoint offset
				4. recompute state forward

		R4 — Replay Rule
			replay(event_log, start_offset, end_offset):

			FOR event IN EventLog[start_offset → end_offset]:
				apply deterministic transition

			RETURN state

			(MUST match Step 4 transition rules exactly )

			CONSTRAINT:
				start_offset = checkpoint.event_offset
				end_offset = target recovery point

			Replay MUST use ordering defined in:

				Step 3 — Event Ordering Model
				Step 6 — Execution Ordering

				No independent ordering allowed

			REPLAY MODE DEFINITION (MANDATORY):

				Replay operates in two explicit modes:

				1. RECOVERY MODE
				   Purpose:
					   reconstruct state from checkpoint_offset → target_offset

				2. VALIDATION MODE
				   Purpose:
					   recompute full state from EventLog[0 → t] for equivalence check

				Constraint:

				- modes MUST be explicitly specified
				- implicit mode selection is FORBIDDEN

		R5 — Replay Determinism Rule

			Replay MUST match:

				state_hash
				snapshot_hash
				output_stream

			Violation → HARD FAIL

		R6 — Failure Reconstruction Rule
			failure_point = first mismatch(
				live_state_hash,
				replay_state_hash
			)

		R7 — Consistency Validation Rule
			snapshot_hash == HASH(EventLog[0 → t])

			(Aligned with Step 2 + Step 4 invariants)

	5.5 RULE EXECUTION ORDER (STRICT)
			Checkpoint Validation
			Snapshot Validation
			Recovery Execution
			Replay Execution
			Consistency Validation
			Failure Reconstruction
