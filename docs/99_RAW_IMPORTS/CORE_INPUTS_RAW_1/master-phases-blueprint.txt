SECTION: CONTROLLED EXTERNAL INPUT LAYER (CEIL)

	Define:

	CEIL is a system-level input control layer that allows externally generated trade intents to enter the trading platform under strict validation, risk, and policy enforcement.

	CEIL is NOT:

		part of Phase A (trading logic)
		part of Phase B (constraints)
		part of Phase C (infrastructure)
		part of Phase D core logic

	CEIL acts as an additional input channel at the Trade Intent boundary.

	DEFINITION CONSTRAINT

		External Source is defined as:

			any system outside Phase A–D that generates trade intents

		Validation Complete is defined as:

			all CEIL validation rules satisfied with no violation


	SYSTEM POSITION

	Core Flow:
		Market → Strategy → Signal → Decision → Trade Intent

	CEIL Flow:
		External Source → CEIL → Validated Trade Intent

	Merge Point:
		Core Trade Intent + CEIL Trade Intent
				↓
			Risk Engine
				↓
			Policy Engine
				↓
			Execution


	INPUT CLASSIFICATION (MANDATORY)

	Every trade intent MUST include:

		origin_type ∈ {CORE, EXTERNAL}

		CORE:
			generated by Decision Engine

		EXTERNAL:
			generated outside core system

	CANONICAL INPUT SET (MANDATORY)

		External inputs MUST be processed using:

			canonical_external_input_set = {
				external_trade_intent_snapshot
				configuration_snapshot
				version_identifiers
			}

		Constraints:

			snapshot MUST be immutable
			snapshot MUST be complete (no implicit fields)
			snapshot MUST be hash-identifiable

		All CEIL processing MUST use ONLY canonical_external_input_set

	DETERMINISTIC IDENTITY (MANDATORY)

		Each external trade intent MUST have a deterministic identifier:

			external_intent_id = HASH_v1(canonical_external_payload)

		Where canonical_external_payload includes:

			instrument
			direction
			size
			timestamp
			source_identifier

		Constraints:

			canonical field order MUST be fixed
			identical payload MUST produce identical external_intent_id

		Purpose:

			ensures deduplication
			ensures replay consistency
			ensures traceability


	ISOLATION RULES (STRICT)

	External inputs MUST NOT:

		enter Strategy layer
		enter Signal model
		enter Decision engine

	External inputs MUST NOT:

		influence signal generation
		influence decision aggregation
		modify system parameters


	VALIDATION REQUIREMENTS

	All external inputs MUST pass CEIL validation:

		schema validation
		instrument validity
		timestamp validity
		duplication check
		completeness check

	If validation fails:
		input MUST be rejected

	DUPLICATION RULE (MANDATORY)

		External trade intents MUST be uniquely identified by:

			external_intent_id

		Constraint:

			if external_intent_id already exists within active validation window:

				duplicate MUST be rejected

			OR

				duplicate handling MUST follow deterministic rule:
					(e.g., first accepted, subsequent rejected)

		No implicit duplication handling allowed

		ACTIVE VALIDATION WINDOW (MANDATORY)

			Active validation window MUST be defined as:

				time interval = [current_time - max_allowed_delay, current_time]

			Constraint:

				duplication checks MUST operate ONLY within this window

			Window definition MUST be globally consistent

	RULE EXECUTION ORDER (MANDATORY)

		External input processing MUST follow strict sequence:

			1. Validation (CEIL)
			2. Risk Engine
			3. Policy Engine
			4. Execution

		Precedence:

			Risk Engine MUST execute BEFORE Policy Engine

			If Risk rejects:
				Policy MUST NOT execute

			If Policy rejects:
				Execution MUST NOT proceed

		No reordering permitted

	INPUT DOMAIN CONSTRAINTS (MANDATORY)

		Validation MUST enforce:

			size > 0
			instrument MUST exist in reference universe
			direction ∈ {BUY, SELL}
			timestamp MUST be within valid time window

		Invalid domain values MUST be rejected

		Schema-valid but logically invalid inputs MUST NOT be accepted

	TIME VALIDITY CONSTRAINT (MANDATORY)

		External trade intent MUST satisfy:

			current_time - timestamp ≤ max_allowed_delay

		Where:

			max_allowed_delay is globally defined

		If violated:

			input MUST be rejected as stale

	ORDERING RULE (MANDATORY)

		External inputs MUST be processed in deterministic order:

			ordered by:

				1. timestamp (ascending)
				2. external_intent_id (lexicographic)

		Constraint:

			identical input set MUST produce identical processing order

		No runtime-dependent ordering allowed


	RISK ENFORCEMENT (MANDATORY)

	All CEIL inputs MUST pass Risk Engine.

	Constraints:

		stricter limits than CORE
		bounded capital usage
		exposure caps
		loss limits

	Risk Engine may:

		reduce
		reject
		terminate


	POLICY ENFORCEMENT (MANDATORY)

	Policy Engine acts as final approval.

	Policy may:

		allow
		restrict
		reject


	CAPITAL PARTITIONING (MANDATORY)

	System MUST define:

		Core Capital
		External Capital

	Constraints:

		External capital MUST be isolated
		External inputs MUST NOT use core capital

	INPUT RATE CONTROL (MANDATORY)

		System MUST enforce:

			maximum external inputs per instrument per time window

		If exceeded:

			excess inputs MUST be rejected deterministically

		RATE LIMIT ENFORCEMENT RULE

			If rate limit exceeded:

				inputs MUST be rejected in deterministic order:

					lowest priority = latest timestamp

					tie-breaker = highest external_intent_id

			No random rejection allowed


	NO FEEDBACK RULE (CRITICAL)

	CEIL outputs MUST NOT feed into:

		strategy design
		signal model
		decision engine


	KILL SWITCH (MANDATORY)

	System MUST support:

		independent CEIL shutdown
		zero impact on core system


	TRACEABILITY

	Each external trade MUST include:

		origin_type = EXTERNAL
		source_identifier
		validation_status
		risk_decision_reference
		policy_decision_reference

	TRACEABILITY IDENTITY (MANDATORY)

		Each external trade MUST include:

			external_intent_id

		Constraint:

			all downstream references MUST use this identifier

			trace must be reconstructable from canonical input


	FAILURE CONDITIONS

	CEIL fails if:

		validation is bypassed
		risk is bypassed

		capital isolation is violated
		feedback into core system exists
