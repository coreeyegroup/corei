- Every production source file must begin with an institutional documentation header.
- Every source file must clearly define why it exists.
- Every source file must clearly define its purpose.
- Every source file must clearly define its responsibilities.
- Every source file must clearly define what it must never do.
- Every source file must clearly define its dependencies.
- Every source file must clearly define its consumers.
- Every source file must clearly define its architectural position within COREI.
- Every runtime component must clearly define its lifecycle where applicable.
- Every source file must have a single primary responsibility.
- Responsibilities must be explicit.
- Architectural boundaries must be explicit.
- Dependencies must be intentional.
- Consumers must be identifiable.
- A source file without a clearly defined purpose should not exist.
- A source file without clearly defined responsibilities is incomplete.
- A source file without clearly defined boundaries is incomplete.
- A source file without architectural context creates drift.
- A source file without clear dependencies creates unnecessary coupling.
- A source file without identifiable consumers creates ambiguity.
- Documentation is not decoration.
- Documentation preserves understanding.
- Understanding preserves architecture.
- Architecture preserves continuity.
- The source code is the authoritative architectural documentation of COREI.
- Every implementation must improve maintainability, knowledge transfer, architectural integrity, and institutional quality.
- Every source file must improve understanding before implementation.
