# ENGINEERING AUTHORITY MODEL

## AUTHORITATIVE PURPOSE

This document defines authority precedence across the CORE platform.

When conflicts occur, higher authority wins.

---

# AUTHORITY HIERARCHY

| Priority | Authority |
|------------|------------|
| 1 | Architecture |
| 2 | Governance |
| 3 | Validation |
| 4 | Documentation |
| 5 | Delivery Speed |

---

# AUTHORITY DEFINITIONS

## ARCHITECTURE

Defines:

- ownership
- boundaries
- system design
- responsibility allocation

Architecture is the highest authority.

---

## GOVERNANCE

Defines:

- engineering laws
- lifecycle rules
- operational standards
- decision frameworks

Governance cannot violate architecture.

---

## VALIDATION

Defines:

- correctness
- determinism
- replay safety
- recoverability

Validation cannot violate architecture or governance.

---

## DOCUMENTATION

Defines:

- institutional knowledge
- operational guidance
- implementation records

Documentation reflects reality.

Documentation does not define reality.

---

## DELIVERY SPEED

Defines:

- execution velocity
- delivery timelines
- implementation urgency

Speed is always the lowest authority.

---

# GLOBAL RULES

Speed never overrides validation.

Validation never overrides architecture.

Governance never violates architecture.

Documentation reflects implementation.

Architecture is final authority.
